# TeamEC新体系（パピー用・試算）

請求書発行ページで **クライアント「Team-EC」・対象月 2026年9月以降** を選ぶと、自動でこの新体系の画面になる。
8月以前のTeam-EC、他クライアントは従来の処理のまま。別クライアントは作らない（選び間違い・二重請求を構造的に防ぐ）。
Eシス出荷実績の取込と正式出力（MF CSV・履歴・Drive）が未接続のため、現在は試算専用。

## 構成

- `__init__.py`：分岐判定 `applies(client, year, month)`。
- `rules.py`：計算。単価は **料金の版 `VERSIONS`** が正本。
  - 改定時は既存の版を書き換えず、新しい版を末尾に追記する（料金表に「9〜11月暫定、12月に検証して確定」とある）。
  - 料金表との差分は `overrides` だけ（出荷指示作成料1,200円/回）。
- `source_rates.json`：本人指定「新料金単価表」A17:H64 の2026-10-02取得版（根拠）。
  版と取得版が食い違うと `tests/test_teamec_new.py` が落ちる。料金表に単価のある行が版に無くても落ちる。
- `ui.py`：画面。上から順に確認する縦長の構成で、各段は「確認済み」で1行にたためる（タブは見落とすため廃止）。
  - 出荷作業料・資材費・送料・出荷稼働日・FBA・ピース入庫：`AIworkspace\teamec-billing-fetch` が作る照合結果JSON。
    Driveの「TeamEC実績」フォルダ（teamec-billing-fetch が同じOAuthクライアントで作成）の `TeamEC実績_YYYY-MM_*.json` の最新を読む。
    無いときは画面からJSONを読み込める。読めなければ金額を出さない。ローカル確認は環境変数 `TEAMEC_RESULTS_DIR`。
  - 保管カウント・イレギュラー作業：既存ページのNotion記録（ここでは再入力しない）。

## 動かし方

- 本番：既存アプリの請求書発行ページ（権限 `invoice`）。新しいSecrets不要。
- 本番反映時に、Team-ECの保管料マスタへ「保管料：当社指定ロケーション／600円」を追加する（保管カウントの選択肢に出すため）。
- テスト：`python -m pytest tests/test_teamec_new.py -q`
- ローカル確認：`AIworkspace\.claude\launch.json` の `teamec-preview`（Notionは見本データ、保存は全て遮断）。

定期実行なし。Notionが読めないときは金額を出さない（0件扱いにしない）。

## 共有シート・依頼台帳・新商品（2026-10-07 経理担当との確認で追加）

照合結果（teamec-billing-fetch）の `台帳` と `新商品` を読む。

- 5. 依頼ごとの作業：随時連絡・返品処理・配送種別/個口数の変更（備考「イーシス」）・新商品 初期設定（棚番が未設定→設定）を、
  根拠が【シート】【Eシス】で始まる行として最初から入れる。人が直す・消すことができる。
- 6. 依頼台帳（たたき台）：その月の依頼を並べ、「計上」にした行だけ明細にする。数量（人時）・実費の単価が空のまま計上にはできない。
- 7. 返品の着払い送料は自動（返品交換シート×ヤマト請求）。応援控除・保管費値引きの根拠欄は廃止。
- 同じ品名・単価の明細は1行にまとめる（FBA対応費が依頼の数だけ並ばない）。
- `台帳` が無い・null の照合結果は「0件とは限りません」と警告を出し、自動の行は入れない。

### 2026-10-08 の変更（本人指示）

- 配送変更：備考は見ない。伝票番号がその月のEシス注文IDに当たる行を拾う（先頭の J は有っても無くてもよい）。
- 返品の送料：ヤマト請求で確かめた金額と、シートの「パピー記入欄」（仮）を別の列に分けた確認表にする。
  ヤマト請求に無い送り状は日本郵便・佐川の追跡で運送会社を確かめ、その会社の請求の確認を促す。「計上する送料」は人が直せる。
- 依頼台帳：依頼の一覧（見るだけ）と、請求のたたき台（依頼×品目の行。追加・削除・変更できる）に分けた。
  品目の候補は `rules.LEDGER_RULES`（文面のキーワード→品目）が正本。当たらなければ汎用作業料を1行出す。

### 画面の並び（2026-10-08 本人指示）

「依頼された内容に対して金額」が基本。1 出荷実績 → 2 出荷稼働日 → 3 保管 → 4 依頼ごとの作業（① 単価が決まっている作業と
返品の着払い送料 → ② 依頼台帳＝内容を見て判別する依頼）→ 5 汎用作業 → 6 控除 → 7 試算 → 8 発行。

- 4 では、表の下に「依頼・作業・単価・数量・金額」と小計をその場で出す。
- 作業の選択肢は単価つき（`rules.event_choices`。版の単価から作る）。事前通知（14日前まで）・時間帯外の到着で単価が変わる作業は
  選択肢を分け、「通知日」「時間外再手配」の列は画面から無くした（計算側の `event_lines` には `choice_rows` で渡す）。

- 4 は確認する元（シート）ごとに「見出し（シート名とリンク）→ 確認表（1シート＝1表）→ 小計」で統一（2026-10-08 本人指示）。
  FBA／随時連絡／返品交換（処理料と送料を同じ行）／配送変更依頼／新商品／そのほか（手で足す）／依頼台帳（内容とたたき台を同じ行）。
  各行の「計上」を外すと請求から外れる。依頼台帳は品目を空にすると請求しない。確認表の元は `rules.sheet_tables`。

### 表の決まり（2026-10-08 本人指示）

- 横スクロールが出る表にしない（見落とすため）。確認表は折り返して全部見える表（`ui._table`＝`st.table`）で出し、
  直す項目は表の外の入力欄（請求しない行の選択・送料の入力）に出す。編集できる表（そのほかの作業・依頼台帳）は5列に絞る。
  収まらないときは代替案を出して本人に確認する。
- 列順はどの表も「名称 → 金額 → 理由（内容）」。内訳明細Excelのシートも同じ（`rules.breakdown_sheets`。2列目は必ず金額）。
- 請求書（MF CSVの詳細）と内訳明細には、社内向けの印（【シート】・仮・自動など）を載せない（`rules._plain`）。
- 確認表は1列に1つの意味だけを持たせる（幅に収めるために列をまとめない。2026-10-08 本人指示で訂正）。
  どの表も同じ形・同じ操作：名称 → 金額 → 計上（チェック）→ 理由。直す項目（返品の「計上する送料」）も表の中で直す。
  入力・確認が要る行は色をつける（`ui._confirm_table` の attention）。列と幅の正本は `ui.SHEET_COLUMNS`（合計960px以内）。
  収まらない列（返品の注文番号・運送会社の根拠）は表から外している。足すときは代替案を本人に確認する。
- 「計上」は確認表の一番左。出荷稼働日の「稼働」も同じ意味なので一番左（2026-10-08 本人指示）。
- 新商品の金額は行ごとに選ぶ（通常700円／14日前までの通知あり・5SKU以上450円／10SKU以上350円。初期値は700円）。
  450円を選んだ商品が5SKU未満、350円が10SKU未満なら計算を止める（`rules.event_lines` の「単価指定」。2026-10-08 本人指示）。
- 返品交換の表から外した「注文番号」「運送会社の根拠」は、表の下のチェックで見られる。
- 依頼台帳の依頼の文面は、表にせず1件ずつ罫線で区切って全文を出す。
