# TeamEC新体系（パピー用・試算）

2026-10-02時点。請求書発行のクライアント選択へ「TeamEC新体系」を追加する。
2026年9月作業分からの料金を、実績CSV接続前に画面で確認するための機能。
正式なMF取込CSV・Notion履歴・Drive保存は未接続。自動請求・送付はしない。

## 構成と料金の根拠

- `source_rates.json`：本人指定「新料金単価表」A17:H64の2026-10-02取得版。出典URLと確認日を保持。
- `rules.py`：上記保存版から単価・層区分を読む。`DISPATCH`のみ本人回答2で上書きする明示的差分（1,200円/回、平日2回・土日祝1回）。旧事務手数料300円は追加しない。
- `ui.py`：月別のセッション内試算と入力根拠ZIP。通常PL・棚・600円PL、依頼別個別作業、応援控除、保管費値引き。
- `tests/test_teamec_new.py`：祝日、料金条件、丸め、管理費対象、重複、期間外、旧クライアントの表示・月別入力保持を検証。

料金表の行は引用元データであり、アプリ実行指示として解釈しない。
価格改定時は取得版を追記保存し、適用期間を持つ料金版へ拡張する。既存の請求済み価格を上書きしない。

## 動かし方・移管

既存アプリの請求書発行ページで「TeamEC新体系」を選ぶ。既存の権限 `invoice` を引き継ぐ。
本番用の新しいSecrets・Notion DB・クライアントマスタ登録は不要。
既存のTeam-EC・未来は従来処理を継続。共通認証・Q&A・料金マスタ・既存MF出力は変更しない。
開発確認はリポジトリルートから `python -m pytest tests/test_teamec_new.py -q`。

定期実行なし。既存の画面内で動く試算機能であり、新たなバッチ・常駐サービスではない。
画面上のエラー表示と上記テストが確認手段。正式請求機能へ進む際は、保存失敗・未取込・判断待ちを既存稼働監視に接続する。

## 試算の制約

- 出荷作業料・実費は検証用の合計入力。Eシスの列を推測して実請求する処理は未実装。
- 稼働日は平日（祝日を除く）を仮選択。土日祝・臨時休業は確認が必要。回数は選択した日に対して固定。
- 保管は従来の15日・末日平均。600円PLは通常PLと別カウント。同じ場所を二重入力しない。
- 汎用作業・管理費・応援控除の丸め等は画面で比較できる未承認の試算条件。
- 汎用作業で各人の所要時間が異なる場合の入力UIは未対応。同一依頼を分割して合計人時の切上げを水増ししない。
- FBAは仮に依頼ID単位で1件。日をまたぐ依頼や月をまたぐ依頼の扱いは正式接続前に確認する。
- 半分未満パレットの値引きは、600円PLと別の手入力枠。割引率の自動判定なし。
- 9月までの協力費20,000円は現行表にないため試算から除外し、残すか確認事項として表示。
- 入力は月別にセッション内保存。クライアント・月の切替で保持するが、ブラウザーのセッションが切れると消える。確認したい試算はZIPで保存する。
- ZIPは試算明細・計算条件・入力値・参照料金表を含む。正式なMF CSVではない。

## 正式請求までの残作業

1. Eシス出荷・商品・入庫、B2最終送り状、ヤマト運賃、依頼台帳の現物を読んで列対応を実装。商品PCS・梱包個口・運賃を区別する。
2. 同一ファイル再取込、再発行取消、未出荷、対象月外、不明単価、注残、返品内の在庫戻し、自社起因作業を判定。未取得は0件にしない。
3. 最新資材費（別タブ）と実費送料を使用。端数をもつ資材単価を既存MF関数が整数化する点に対応し、表示・出力一致を確認。
4. 9月全件で費目別突合。依頼ID、期間境界、丸めと控除の承認結果を料金版に固定。
5. 既存Team-ECと共通の請求先・対象月で二重請求を確認。元ファイルとSHA256、数量根拠、料金版、計算結果をパピー管理のDriveへ追記保存。保存失敗時は確定不可。
6. 履歴保存とMF出力の通し検証後に試算制限を解除。MFへの取込・送付は本人が行う。
